# Chrome Keep-alive：服务端安装

这份说明只讲保活服务这个程序怎么放、怎么启动、怎么停。脚本怎么写、掉线了谁去登录，看同目录的《保活维护》。发帖和下载看同目录的《日常发布》。

保活服务是服务器上的一个 Node 进程。QiziShell 在另一台 Mac 上，只用来看状态和转发掉线通知，不能代替启动。

所有平台都用这一份程序自带的保活窗口，不再使用系统里的 Google Chrome。视频号、小红书以及以后新增的平台，都是这一个窗口里的页签。窗口可以收在屏幕顶部菜单栏。

## 前提

在这台机器上确认两件事：

```
node -v
```

需要 Node.js 18 或更高。

这台机器的用户要处于已登录的图形界面。用屏幕共享看着也算。停在登录窗口时，保活窗口起不来。

不要安装、不要启动 Google Chrome 来跑保活。不要使用 9222 端口，也不要另建 `weixin-publish` 之类的用户目录。

## 第一次安装

如果当前目录里已经有 `server.js` 和 `package.json`，跳过解压，直接看下面的 `npm install` 和启动。

安装包文件名是 `qizi-keepalive-server-0.2.0.tgz`。在你要放置它的目录执行：

```
tar -xzf qizi-keepalive-server-0.2.0.tgz
cd qizi-keepalive-server
npm install --omit=dev
```

`npm install` 装上内置浏览器的安装包。浏览器文件大约一百多兆。第一次打开某个平台时，如果文件还不在，保活服务会自己下载并解压，窗口随之下一次重试打开。这台机器访问 GitHub 不稳时，下载走 `https://npmmirror.com/mirrors/electron/`。

## 启动

在含有 `server.js` 的目录执行：

```
mkdir -p ~/.qizi-keepalive
nohup node server.js >> ~/.qizi-keepalive/keepalive.log 2>&1 &
```

想盯着日志看，就前台运行 `node server.js`。这个终端关掉，保活服务就停了。保活窗口不会跟着停。

启动成功时，日志里有这一行：

```
keep-alive server listening on 0.0.0.0:18990
```

平台的开关开着时，日志里还会出现「保活窗口已启动」。多个平台只启动一个窗口，后开的平台是窗口里新的保活页签。

第一次启动还会在这个程序目录里生成「保活」图标（`保活.app`）。

## 再打开窗口

点窗口的关闭按钮，或菜单栏里的「收起」，窗口收进屏幕顶部菜单栏，并没有退出。点菜单栏上的保活图标，或右键选「展开」，窗口回来。

菜单栏右键「退出」会关掉保活窗口。保活服务还在跑、平台开关还开着时，服务自己会把窗口再打开。想马上看到，双击程序目录里的「保活」。

「保活」图标的用法：

- 服务已经在跑：双击把窗口展开。窗口刚被退出时，双击会马上再打开。
- 服务没在跑：双击在后台启动服务。开关开着的平台会随之打开窗口。

不要为了看窗口再执行一次 `node server.js`。端口已被占用时，第二次启动会自己退出。

## 确认已经在跑

```
curl -s http://127.0.0.1:18990/api/state
```

返回的 JSON 里 `"ok": true` 就是在跑。`platforms` 是空数组也正常：平台要在 QiziShell 的 Chrome Keep-alive 窗口里添加，启动本身不创建平台。

每个平台的 `platform.browser` 应为 `shell`。连接页面时用该平台状态里的 `cdp_http`，不要用平台配置里各自的端口号。多个平台的 `cdp_http` 是同一个地址。

## 已经在跑就不要再启动

再执行一次 `node server.js` 会因为端口被占用而退出，日志里是 `port 18990 is already in use`。先用上面的 `curl` 看现有进程，不要开第二个。

查正在监听的进程：

```
lsof -nP -iTCP:18990 -sTCP:LISTEN
```

## 停掉服务

停的是 Node 进程。保活窗口继续开着，下次启动会接管它。

```
kill <上面 lsof 看到的 pid>
```

不要 `kill` 保活窗口的 Electron。那样会把所有平台的页面一起关掉。

## 现在这个阶段

机器重启后保活服务不会自己起来，需要再执行一次启动命令。保活服务在跑的时候，保活窗口崩溃或被关掉，会自动重新拉起。

## 数据放在哪

默认目录 `~/.qizi-keepalive/`：

| 路径 | 内容 |
| --- | --- |
| `config.json` | 平台配置，以及本机 Hermes 地址 |
| `state.json` | 开关、暂停、占用锁 |
| `scripts/<平台ID>.json` | 保活脚本 |
| `shell/` | 所有平台共用的保活窗口。登录留在这里，收起窗口不会清掉 |
| `downloads/` | 在保活窗口里下载的文件 |
| `keepalive.log` | 运行日志 |

换端口或换数据目录：

```
node server.js --port 18990 --data-dir ~/.qizi-keepalive
```

这台机器上 Hermes 面板是 `http://127.0.0.1:9119`。`notify.hermes_url` 要填这个本机地址。公网名字在这台机器上解析不了。

## 地址

接口在本机，默认端口 18990：

```
http://127.0.0.1:18990
```

三份说明也可以从这里读：

```
GET /api/agent-guide/install
GET /api/agent-guide/maintainer
GET /api/agent-guide/publish
```

## 给 Agent 的运行约定

发布、下载、改脚本、重新登录，都连进这一个保活窗口。

- 调试地址用接口返回的 `cdp_http`。
- 保活页在窗口顶上「保活」一组。发布或下载另开的页面在这组外面，做法写在《日常发布》。
- 不要自己启动浏览器，不要 `browser.newPage()`。那样开出的窗口没有这份登录。
