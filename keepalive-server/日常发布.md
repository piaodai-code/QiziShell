# Chrome Keep-alive：日常发布

这份说明给在保活窗口里发内容、上传、下载的 Agent。每个发布 Agent 都按这份做。保活服务怎么启动、脚本怎么写、掉线了谁去登录，不在你这里，那是维护 Agent 的事，见同目录的《保活维护》。

你只做发布和下载：占锁、连进已经开着的保活窗口、做完关掉自己的临时页、解锁。

微信视频号和小红书在同一个窗口里，窗口可以收在屏幕顶部菜单栏。收起之后页面仍然可操作，不要为了发布去把它点开。窗口顶上「保活」一组是这两个平台的常驻页。你的发布页、下载页在这组外面，标题一般是「临时页」。

调试端口以接口返回的 `cdp_http` 为准。这两个平台是同一个端口、同一个窗口。

## 地址

保活服务和你在同一台机器上。

```
http://127.0.0.1:18990
```

请求和响应都是 JSON。成功时 `ok` 为 `true`。失败时 `ok` 为 `false`，`error` 是一句中文原因。409 表示和当前状态冲突，最常见的是锁被别人占着。

下文 `{id}` 是平台 ID。以 `GET /api/platforms` 返回的为准。当前是：

| 平台 | `{id}` |
| --- | --- |
| 微信视频号 | `channels_01` |
| 小红书 | `Xiaohongshu_01` |

`Xiaohongshu_01` 大小写要照写。

## 发布前先看状态

```
GET /api/platforms/{id}
```

用响应里的这些字段决定能不能发：

| 字段 | 可以发的条件 |
| --- | --- |
| `platform.status.browser_alive` | `true`。表示这个平台的保活页已经打开，并且网址已经落到它自己的主机名上。为 `false` 时不要连，告诉用户 |
| `platform.status.session.status` | `alive`。`logged_out` 表示掉线，登录由维护 Agent 处理，你不要自己去扫码登录 |
| `platform.status.awaiting_login` | `false` |
| `platform.status.lock` | `null`，或者 `owner` 就是你自己 |
| `platform.status.cdp_http` | 连 CDP 只用这个地址。所有平台共用一个窗口，所以地址相同，例如 `http://127.0.0.1:9333` |
| `platform.status.shared_window` | `true` 时不要用平台配置里的 `cdp_port` 去连。那个数只是配置编号，窗口并不监听它 |

`session` 为 `null` 或 `unknown` 时，登录状态还没确认。先不要发，告诉用户。

`pages` 只列出这个平台的页签，每条有 `platform_id` 和 `group`。`group` 为 `keepalive` 的是保活页，不要关，也不要把它导航走。`group` 为 `work` 的才是你的临时页。别的平台的页签不会出现在这里。`cdp_ws` 是这一个共享窗口的浏览器级 WebSocket 地址。入口网址在 `platform.entry_url`。`status.chrome_pid` 和 `status.shared_window_pid` 是共享窗口的进程，不是这个平台单独的进程。

## 占用锁

保活到点会点击、切换这个平台的常驻页。你正在上传或填表时被点到，发布会断。所以：

**打开临时页之前先占锁。发完或下载完，无论成功还是失败，都要解锁。**

`owner` 用你自己的 Agent ID，每个发布 Agent 各用各的。不要写 `maintainer`，也不要和别的发布 Agent 用同一个名字。

```
POST /api/platforms/{id}/lock
{ "owner": "你的 Agent ID", "reason": "发布视频", "ttl_minutes": 30 }
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `owner` | 是 | 解锁时必须用同一个值 |
| `reason` | 否 | 显示在用户的监控窗口里，写清在发什么或下什么 |
| `ttl_minutes` | 否 | 这把锁多少分钟后自动解除，1–1440。不填则用该平台的默认值，初始是 10 分钟 |

10 分钟经常不够一次发布。按这次可能用的时间填写 `ttl_minutes`。做到一半发现还要更久，用同一个 `owner` 再调一次 `lock`，到期时间从当前时刻重新算。

收到响应里的 `ok: true` 之后才能开始操作页面。如果正好有一轮保活在执行，这个请求会等那一轮结束再返回，可能要等几分钟。

别人占着时返回 409，`error` 里写明是谁、最晚何时解除。等它解除再重新 `lock`。不要在别人占着时操作页面，也不要用别人的 `owner` 去解锁。

```
POST /api/platforms/{id}/unlock
{ "owner": "你的 Agent ID" }
```

锁到期会自动解除，保活会恢复点击。那是防止你中途出错后页面一直被占着。到期前要做完，或者续锁。不要靠到期来解锁。

发布失败、下载失败、你自己中断、连接断开，只要你还能够发请求，就先关掉临时页，再 `unlock`。

## 在这个窗口里打开发布页

占锁成功之后按这个顺序。一次发布或一次下载，从头到尾只有你这一个临时页。

1. 用 `cdp_http` 连上已经开着的窗口。不要新开浏览器，不要退出窗口，不要清除 Cookie。Playwright 要这样连，否则会去调用这个窗口不支持的接口：

```js
const browser = await chromium.connectOverCDP(cdpHttp, { timeout: 15000, noDefaults: true });
```

2. 用接口返回的 `pages` 认出保活页：`group` 为 `keepalive` 的那一条。连上 CDP 之后，在所有 context 的 `pages()` 里找网址与它相同的那一页。这个页签留在原地。不要关它，不要在里面点菜单，不要 `goto` 到别的地址。另一个平台的保活页不在这份 `pages` 里，也不要去关。

3. 在这个保活页里打开一个临时页，网址用这次要去的第一页，必须是完整网址：

```js
await keepPage.evaluate((url) => window.open(url, '_blank'), firstUrl);
```

`window.open` 会被窗口接住，放进「保活」这组外面。登录和保活页是同一份，可以接着发、接着下。

然后在 `pages()` 里找到这个新页（主机名变成你打开的那个，并且不是刚才那个保活页）。等它出现，最多等 15 秒。

4. 之后要去作品管理、数据中心、发布页、下载页，一律在这个临时页上 `page.goto(网址)`。不要再 `window.open`，不要 `browser.newPage()`，不要 `context.newPage()`，不要 `Target.createTarget`，不要请求 `/json/new`。那些会再开出一个窗口，登录带不过去。

5. 做完，对临时页 `page.close()`，然后 `unlock`。保活页留着。断开 CDP 用连接上的 `browser.close()`，它只断开你自己。不要发浏览器的 `Browser.close`，不要结束 Electron 进程。

换页用网址，不用点击侧栏、顶栏或任何会打开新页的菜单。菜单文字会被挤成图标；点了也会再多出一个临时页。

## 上传

要上传的视频、图片、封面，先放在这台服务器上。临时页里的文件选择框用 Playwright 的 `setInputFiles`，传入这台机器上的路径。不要从你自己的电脑路径去填，浏览器读不到。

## 下载

下载也在这一个临时页里做。点页面上的下载，或打开文件地址让它开始下。

文件落在这台服务器上，和保活数据目录并列的 `downloads` 里。默认是：

```
~/.qizi-keepalive/downloads/
```

文件名用网站给的名字。同名文件已经在时，会在名字后面加上时间戳，不会覆盖上一份。下完按修改时间认最新的那个文件。

不要用 Playwright 的 `download` 事件，也不要调用 `Browser.setDownloadBehavior`。这个窗口不接那两个接口，文件不会因此改路径。

下载到的文件留在上述目录，交给用户或你的后续步骤。不要把保活页的 Cookie 或登录态拷走。
