启用 QiziShell 会议模式：OpenClaw 网关要准备什么

这份说明给要在 OpenClaw 上启用会议模式、或排查「保存会议 / 开始会议失败」的人。全文可以直接粘贴给正在跑 Gateway 的那台机器上的 agent，让它按下面做配置或检查。会议参数已经可用时，不要重装，不要删除已有会议文件。若 qizi.meetingRecords.list 还不存在，在现有插件上补「已开完的会议全文」那三个方法。

在哪台机器上做

插件和会议文件都放在正在运行 OpenClaw Gateway 的那台机器上。QiziShell 如果连的是远程网关，本机 Mac 的 ~/.openclaw 只是客户端配置，不要在那里装这个插件，也不要改 QiziShell 仓库。

先确认自己就在网关机器上，并且用的是跑 Gateway 的同一个系统用户。状态目录：有环境变量 OPENCLAW_STATE_DIR 就用它，否则是该用户的 ~/.openclaw。能用插件 API 的 resolveStateDir() 就用它，不要写死某一台 Mac 的路径。

先检查是否已经可用

按这个顺序看。四步都通过，就不用再装：

  1. openclaw plugins list 里 qizi-meetings 已启用。
  2. 网关启动日志里有 qizi-meetings（类似 http server listening (... qizi-meetings ...)）。只显示 enabled、但调用报 unknown method，通常是清单里少了 activation.onStartup，或装完后没有重启网关。
  3. 用现有操作员身份调用 qizi.meetings.list，返回 {"meetings":[...]}。不需要 operator.admin。
  4. 存储目录 <状态目录>/qizi/meeting-presets/ 存在，目录权限 0700，里面的 .md 是 0600。
openclaw gateway call qizi.meetings.list --params '{}'

检查时不要删除目录里已有的会议文件。参数存储可用之后，再执行：

openclaw gateway call qizi.meetingRecords.list --params '{}'

返回 {"records":[...]} 才算会议全文也能存。返回 unknown method 时，按「已开完的会议全文」在现有 qizi-meetings 插件里补三个方法，然后重启网关。不要另装一个插件，不要动 meeting-presets。

还没有时要装的插件

不要改 OpenClaw 核心。用官方插件入口 api.registerGatewayMethod 增加 4 个 RPC。方法名必须用插件前缀 qizi.meetings.*。不要用 config.*、exec.approvals.*、operator.admin.*、wizard.*、update.*，那些会被收成 operator.admin。

插件 id：qizi-meetings。目录自己定，例如网关用户家目录下的 qizi-meetings-plugin/。先看这台机器上的 OpenClaw 版本和现有插件怎么写入口。版本和下面示例不一致时，以本机文档为准，但方法名、参数、返回字段不要改。

openclaw.plugin.json 必须带 activation.onStartup: true。没有这一项时，插件可以显示为已启用，方法却永远不会被网关加载。

{
  "id": "qizi-meetings",
  "name": "Qizi meeting presets",
  "description": "Store QiziShell meeting presets as markdown",
  "activation": { "onStartup": true },
  "configSchema": {
    "type": "object",
    "additionalProperties": false,
    "properties": {}
  }
}

package.json 的运行入口按本机插件惯例写。常见写法是 "openclaw": { "extensions": ["./index.js"] }。入口导出默认函数，在里面注册下面 4 个会议参数方法，以及后文 3 个会议全文方法。

不要用 openKeyedStore。第三方插件通常没有这个权限。用普通文件即可。日志里不要打出 Markdown 全文。

会议文件放在哪

目录：<Gateway 状态目录>/qizi/meeting-presets/

目录权限 0700，文件权限 0600。每个会议一个文件：<id>.md。写入先写同目录临时文件，再改名替换，避免写一半。

id 只允许 ^[a-z0-9][a-z0-9-]{0,80}$。拒绝空字符串、..、绝对路径、斜杠和其他字符。QiziShell 保存时用的 id 是 m 加上议题 UTF-8 的 SHA-256 十六进制前 32 位，不要改成议题原文当文件名。

服务端只原样保存 Markdown，不要解析或改写正文，不要补 front matter，不要改换行，不要格式化。

四个方法

list 和 get 用 operator.read；put 和 delete 用 operator.write。不要要求 operator.admin。QiziShell 连接时已经申请这两个 scope。

api.registerGatewayMethod("qizi.meetings.list", handler, { scope: "operator.read" });
api.registerGatewayMethod("qizi.meetings.get", handler, { scope: "operator.read" });
api.registerGatewayMethod("qizi.meetings.put", handler, { scope: "operator.write" });
api.registerGatewayMethod("qizi.meetings.delete", handler, { scope: "operator.write" });

成功时 respond(true, payload)。失败时按本机其他插件的写法 respond(false, undefined, error)，错误里要有人能看懂的 message。

  • qizi.meetings.list 参数 {}。返回 {"meetings":[{"id","topic","savedAt"}]}，savedAt 新的在前。只读每个文件开头的 front matter。没有 topic 时用 id。没有 savedAt 时用文件修改时间的 ISO 字符串。front matter 坏了也要列出该文件，不要让整个 list 失败。不要返回正文。
  • qizi.meetings.get 参数 {"id":"..."}。返回 {"id","markdown"}，markdown 是文件全文。文件不存在就失败，不要返回空字符串冒充成功。
  • qizi.meetings.put 参数 {"id","markdown"}。返回 {"id","bytes"}。markdown 必须是非空字符串，最长 256000 个字符。已存在则整篇覆盖。
  • qizi.meetings.delete 参数 {"id"}。返回 {"id","deleted":true}。文件本来就不存在时返回成功，deleted 为 false。

已开完的会议全文

这是另一份文件，不要写进 meeting-presets。一场已保存会议对应一篇参数；每场开完的会各有一份全文，同一议题会有很多份。

目录：<Gateway 状态目录>/qizi/meeting-records/。目录权限 0700，文件权限 0600。文件名 <id>.json。id 规则与上面相同。写入先写同目录临时文件，再改名替换。

服务端把 record 当作字符串原样落盘，不要解析后重新格式化，不要改字段，不要截断正文。日志里不要打出全文。

api.registerGatewayMethod("qizi.meetingRecords.list", handler, { scope: "operator.read" });
api.registerGatewayMethod("qizi.meetingRecords.get", handler, { scope: "operator.read" });
api.registerGatewayMethod("qizi.meetingRecords.put", handler, { scope: "operator.write" });
  • qizi.meetingRecords.list 参数 {}。返回 {"records":[{"id","topic","state","startedAt","finishedAt","noRepeatPastTopics","finalSummary"}]}，finishedAt 新的在前。只读这些字段。没有 finishedAt 时用文件修改时间的 ISO 字符串。某个文件不是 JSON 对象时，仍列出该 id，其他字段可空，不要让整个 list 失败。不要返回 transcript、draft、briefingMessage。
  • qizi.meetingRecords.get 参数 {"id":"..."}。返回 {"id","record"}，record 是文件全文的字符串。文件不存在就失败。
  • qizi.meetingRecords.put 参数 {"id","record"}。返回 {"id","bytes"}。record 必须是非空字符串，而且 JSON.parse 的结果是对象，最长 2000000 个字符。已存在则整篇覆盖。解析失败不要写文件。

验收用下面这组，做完删掉 qizi-record-smoke.json。不要删已有记录。

openclaw gateway call qizi.meetingRecords.put --params '{"id":"qizi-record-smoke","record":"{\"id\":\"qizi-record-smoke\",\"topic\":\"验收\",\"finishedAt\":\"2026-10-20T00:00:00.000Z\",\"finalSummary\":\"定为验收\"}"}'
openclaw gateway call qizi.meetingRecords.list --params '{}'
openclaw gateway call qizi.meetingRecords.get --params '{"id":"qizi-record-smoke"}'

必须看到：磁盘上的文件与写入的字符串一致；list 里有这条且带 topic 和 finalSummary，没有 transcript；get 的 record 与写入一致。id 为 ../x 时 put 失败，目录外没有新文件。

启用与重启

在网关所在机器、用跑 Gateway 的同一个系统用户执行：

openclaw plugins install --link <插件目录>
openclaw plugins enable qizi-meetings

本地未受信任的插件如果安装命令要求确认，加上该版本要求的 --force。配置里如果有 plugins.allow，把 qizi-meetings 加进去，并且不要留在 plugins.deny 里。

允许改的配置只有这三处：plugins.entries.qizi-meetings.enabled、plugins.load.paths、plugins.allow。改之前先备份 openclaw.json。

热加载和 plugins reload 不会把新方法挂进正在跑的网关。装完后按这台机器现有的方式重启 Gateway（launchd、systemd 或现有进程），不要另起一个网关。重启后日志里应能看到 qizi-meetings。

一篇会议文件里必须有的内容

QiziShell 点「保存会议」时会自己写成下面的形状：文首是参数，后面是七节会议要求。开始会议时会按议题读回这七节。某一节被删掉、删到只剩标题，或整篇读失败，开会会直接报错，不会退回程序里写死的规则。所以这七个标题必须原样保留，而且标题下面要有正文：

  • ## 篇幅与收尾
  • ## 主持启动任务书
  • ## 主持过程中的要求
  • ## 当轮总结
  • ## 最终总结
  • ## 议事发言要求
  • ## 往期主题

文首字段是：topic、goal、moderatorAgentId、moderatorLabel、participantAgentIds、postMeetingExecAgentId、roundCount（1、2 或 3）、noRepeatPastTopics、savedAt。讨论底稿不在文件里，每次开会时另填。

还没保存过的议题不能直接开始。客户端会提示先保存再开始。

不要做的事

  • 不要改 Agent 工作区，不要写 AGENTS.md、SOUL.md 或其他引导文件。
  • 不要改 openclaw.json 里的模型、渠道、token。
  • 不要给 Agent 加写文件或执行命令的工具。
  • 不要新开端口，不要加 HTTP 上传接口。
  • 不要为了通过检查去放开 operator.admin。如果这 4 个方法报 profile 校验失败，而同一个 token 调用 chat.send 这类 operator.write 方法是成功的，就把准入改成和那些已能用的写方法一致。不要改成未认证可写。
  • 检查时不要删掉 meeting-presets 和 meeting-records 里已有的会议。

尚未安装时的验收

只有方法还不存在、需要新装时才做。做完删掉验收文件。已有会议不要动。

openclaw gateway call qizi.meetings.put --params '{"id":"qizi-smoke","markdown":"---\ntopic: 验收\nsavedAt: 2026-10-20T00:00:00.000Z\n---\n\n# 验收\n"}'
openclaw gateway call qizi.meetings.list --params '{}'
openclaw gateway call qizi.meetings.get --params '{"id":"qizi-smoke"}'
openclaw gateway call qizi.meetings.delete --params '{"id":"qizi-smoke"}'
openclaw gateway call qizi.meetings.list --params '{}'

必须看到：put 后磁盘上出现 qizi-smoke.md 且内容一致；list 里有 id=qizi-smoke、topic=验收；get 的全文与写入一致；delete 后再 list 没有这条。id 为 ../x、/tmp/x、空字符串时 put 失败，并且目录外没有新文件。不带 operator.admin 的现有操作员也能成功。

做完后回报

  • 是检查已有安装，还是新装了一份。
  • 插件目录和 Gateway 状态目录的实际路径。
  • OpenClaw 版本。
  • 4 个方法是否已加载；若重启过网关，写明重启方式。
  • qizi.meetings.list 的结果（有几份会议即可，不要贴出 Markdown 全文）。
  • 方法名或字段如果和上面不一致，写明差异。
